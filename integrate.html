Integrating openmodels into a fork

Read this before wiring the API into anything that drives. The registry hands you source weights and provenance. Turning that into something a car runs is your fork's job, and so is deciding whether it is safe. API examples assume API=https://models.example.com; the reference client needs only the public static mirror.

Start here: use the reference client

Everything below is what clients/reference.py already does correctly — oid verification, visible withdrawal status, and direct downloads from the recorded release. Copy it into your fork rather than hand-rolling curl. The rest of this page explains what it is doing and why.

python clients/reference.py --list
python clients/reference.py --pull <bundle_id> --out selfdrive/modeld/models

1. Pick a model by provenance, not by shape

Ask what configuration a model ran in, then compare it to your own:

curl -s "$API/v1/models/<bundle_id>/provenance"

You get the upstream commit, the host constants in effect there, and every occurrence with its status. There is deliberately no endpoint that tells you two models are compatible — that claim cannot be made from the available data. Check /v1/status for catalog freshness; a stale generated_at means the indexer has stopped, which otherwise looks identical to "upstream shipped nothing".

2. Download every file in the bundle, and verify each one

A bundle is usually more than one file. A split model needs its vision and policy components together — vision alone has no plan, lead, or lane_lines and cannot drive. Keep the filenames from /provenance; the build looks them up by name.

The oid is the sha256. Refuse any blob that does not match — that check is the only thing standing between your fork and a swapped artifact.

curl -s "$API/v1/models/<bundle_id>/provenance" \
  | jq -r '.files[] | "\(.oid) \(.filename)"' \
  | while read oid name; do
      curl -sL "$API/v1/files/$oid/download" -o "$name"
      echo "$oid  $name" | sha256sum -c || exit 1
    done

A 503 means the blob is indexed but not yet mirrored — retry later. A 410 means the upstream LFS object disappeared before it could be archived. Files flagged suspect are upstream git conflict debris rather than models, and they mirror faithfully while being unusable.

Map files to compiler inputs by role, never by filename. Names changed across eras — commit 249cafe renamed driving_policy.onnx to driving_on_policy.onnx with identical content — so an older bundle's on_policy role still arrives as driving_policy.onnx. The role is stable; the filename is not.

3. Apply the host constants

Set LAT_SMOOTH_SECONDS and LONG_SMOOTH_SECONDS to the values from /provenance. They feed lateral delay in controlsd, and comma changes them in the same commit that swaps a model. Shipping new weights against stale constants is the most likely way to get a model that appears to work and steers wrong.

When host_constants_missing is non-empty, that is real information, not a gap to paper over. Older eras predate these constants entirely. The registry reports them absent rather than defaulting them to zero. If you cannot determine a value, treat the model as unqualified.

4. Compile for your target — and check the compiler accepts the architecture

openpilot builds the tinygrad pickle from ONNX during scons, choosing a backend from the hardware present. The QCOM path opens /dev/kgsl-3d0 directly, so a device-usable artifact can only be produced on the device — not in CI.

Upstream's compiler only accepts a vision + on-policy pair. compile_modeld.py requires --vision-onnx and --on-policy-onnx; there is no --supercombo-onnx and no off-policy input. Combined supercombos need a multi-era compiler such as sunnypilot's. Check the bundle's roles rather than relying on an era-wide count.

--frame-skip is also required, and scons derives it from your ModelConstants.MODEL_RUN_FREQ // MODEL_CONTEXT_FREQ — it is a host property, not a model property. Provenance reports what the model ran with upstream, so a difference from your own value is a mismatch signal worth investigating rather than a number to copy blindly.

python selfdrive/modeld/compile_modeld.py \
  --vision-onnx    selfdrive/modeld/models/driving_vision.onnx \
  --on-policy-onnx selfdrive/modeld/models/driving_on_policy.onnx \
  --model-size 512x256 --camera-resolutions 1928x1208 1344x760 \
  --frame-skip 4 --output selfdrive/modeld/models/driving_tinygrad.pkl

Runtime model switching is where the cost lands. A settings-menu picker cannot re-run scons per selection, so it must invoke the compiler on-device: multi-minute, offroad-only, and it needs a progress UI, a disk budget, and a rollback path for a compile that fails or is interrupted.

5. Make withdrawal status impossible to miss

Filter to status=merged unless a human explicitly opted in. A reverted model is one comma pulled back, and "merged" is not the same as "approved" — several models landed and were reverted days later. PR-only models never cleared review at all. The reference client shows every status and offers --merged-only when a product chooses to hide withdrawn entries.

curl -s "$API/v1/models?status=merged&kind=driving"

What the registry never establishes

Target-hardware compilation, process replay, latency and memory behaviour, closed-loop driving quality, or safety. Everything served here is storage integrity and upstream history. Two models can share every tensor shape while interpreting those numbers completely differently, which is why no endpoint will ever tell you they are interchangeable. Qualify a model on your own hardware before anyone drives on it.

This registry asserts blob identity and upstream provenance. It does not assert that a model is safe to drive, or that two models are interchangeable.
