Compose a model

Combine a vision component with an on-policy component — and optionally an off-policy component alongside it — and get a code you can paste into a model picker. The on-policy component carries the control outputs and is what compiles on device; the off-policy component carries the full plan and is the optional extra comma trains alongside it. But the exact combination you build here has never been driven.

Redeeming it — GET /v1/compose/<code>, or redeem_code() in the runtime library — resolves it against the catalog and re-runs every check. A damaged code fails to resolve rather than quietly naming different weights.

Before you drive it

Structural checks passing is not a safety result. The components may carry different host constants, since they came from different commits — redeem the code to see both and choose deliberately. Then compile on-device and qualify it yourself.

This registry asserts blob identity and upstream provenance. It does not assert that a model is safe to drive, or that two models are interchangeable.
