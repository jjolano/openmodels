## Platform
web

## Users and purpose
Developers integrating universal openpilot model discovery, composition and installation into consumers such as moonpilot, openpilot and sunnypilot.

## Confirmed workflow
The primary surface is a composition workspace: choose an architecture, select contextual components, inspect source settings, and export a request and runnable SDK code. The Python SDK performs composition validation. Model browsing and developer documentation support this workflow.

## Constraints
Static GitHub Pages; no backend or browser Python runtime required. Preserve schema 1, exact document identity, source contexts, missing settings, and existing downloads. Consumers own support policies, installation, qualification and activation. The browser must not claim a request is a validated recipe. Paginate libraries at 30 results and load detail on demand.

## Brand commitments
The approved direction is a technical instrument panel: graphite surfaces, crisp divisions, compact readable controls, monospace data/code, cyan selection and amber missing information. Light/dark themes, keyboard access and a stacked mobile workflow are required.
